statistical-arbitrage

A self-contained statistical-arbitrage toolkit implemented four times — Python (reference), C++17, Rust and Java 21 — against one pinned numerical contract. OLS, the ADF unit-root test with MacKinnon (2010) finite-sample critical values, Engle–Granger, a Johansen-lite trace test with a native Cholesky + Jacobi eigensolver, a Kalman dynamic hedge ratio, rolling z-score signals and a dollar-neutral pairs backtest with next-close execution are each specified down to the solver in API_SPEC.md, so all four languages reproduce 24 golden cases to 1e-6..1e-10 and the same exact trade count. No RNG at runtime; the reference is cross-validated against statsmodels before any golden is written.

What the latest review found and fixed. Two defects that a desk would hit in exactly the samples it uses. The backtester executed an entry signalled at day T−2 at the final close and force-closed it at that same close, reporting a phantom zero-day round trip that paid two costs and distorted trade count, win rate, holding period and Sharpe on every rolling daily re-run; the pinned rule now discards a pending entry at the end of data (a pending exit still executes), and the discard is golden-tested on hand-built spreads and property-tested over every truncation of the bundled pair. The ADF and Engle–Granger tests used asymptotic critical values, which on 60-day rolling screens systematically over-detect cointegration (the 2-variable 5 % value is −3.34 asymptotically but −3.46 at T_eff = 50); every port now evaluates the MacKinnon (2010) finite-sample response surface at the actual regression size and refuses T_eff < 20. Finite-parameter checks, day-column monotonicity and config re-validation were added in the same pass; 3 golden cases were added (24 total) with the 21 existing values unchanged. Known limits: P₀ = 1e3·I is not diffuse for four-digit prices, stops fire on favourable overshoots too, and returns are on notional, not compounded.

What's inside

OLS & ADF

ols.py: normal equations with a pinned LU solve, plain standard errors, t-stats and R². adf.py: augmented Dickey–Fuller with a fixed lag (default 1), constant and no trend, MacKinnon (2010) finite-sample critical values at the regression sample size (T_eff ≥ 20, maxlag ≤ 1000) and an interpolated approximate p-value that is never used for a verdict.

Engle–Granger & Johansen-lite

engle_granger.py runs the hedge OLS then the residual ADF against the 2- or 3-variable EG table. johansen.py is the 2–3 asset VECM with an unrestricted constant and k = 1 lagged difference, solved with a native Cholesky factorisation and cyclic Jacobi eigensolver against the Osterwald–Lenum 95 % trace table — no small-sample correction, trace test only, and collinear inputs are rejected.

Half-life & Kalman hedge

Half-life from an AR(1) fit on the spread, hl = −ln 2 / ln(1 + ρ), with the sentinels +inf and 0.0 both meaning "do not trade" — pinned in every port. kalman.py tracks a random-walk state (αₜ, βₜ) with RiskMetrics-style Q = δ/(1−δ)·I, a Joseph-form covariance update and innovation z-scores; r must be finite and positive.

Signals & pairs backtest

signals.py: a current-observation-inclusive rolling z-score (ddof = 1, zero-variance guard). backtest.py: a FLAT/LONG/SHORT state machine with next-close execution, equal-dollar legs sized to capital/2 at every entry, basis-point costs plus slippage, |z| ≥ stop_z stops with same-direction re-entry allowed the next day, full metrics (total and annualised return, Sharpe, max drawdown, trades, win rate, holding period, turnover, stops), and a walk-forward split that estimates the hedge in-sample and trades it out-of-sample.

Bundled data

pair_equity.csv: 1500 days of a cointegrated pair with true beta 1.7 and a break to 1.1 at day 1050. fx_triangle.csv: EURUSD vs a GBPUSD × EURGBP basket, cointegrated in logs, recovering the (1, −1, −1) triangle vector. random_walks.csv: two independent walks for the spurious-regression case. config.json holds the signal and cost parameters shared by all four demos; generate_data.py regenerates everything from fixed seeds.

Golden suite & testing

Every language loads the same golden.json and asserts each scalar within its tolerance, so a different lag convention, a non-Joseph update or a different z-score window fails immediately. Beyond goldens, each port carries the same behavioural suite: accounting identity, exact dollar neutrality at entry, next-close execution, the end-of-data discard rule on hand-built spreads with closed-form z-scores, the every-truncation "no zero-day trade" property, stop/re-entry timing, negative-equity metrics, walk-forward length checks and loader validation.

Units, timing, scope

Prices are raw levels in whatever unit you pass (the FX example uses logs because cross-rate identities are multiplicative); alpha, beta, the Kalman r and P₀ share those units. One row is one equally spaced observation, 252 periods per year and the one-close execution lag are hard-coded. Out of scope: calendars and day-count, intraday data, financing and borrow, market impact, position compounding, rolling diagnostics helpers, automatic lag selection, Johansen deterministic-term variants and p-values.

Error contract

ValueError / std::invalid_argument / Err(StatarbError) / IllegalArgumentException for lengths, finiteness, emptiness, constancy, collinearity, parameter domains and window bounds at every public entry point; config structs are re-validated at run time in C++ and Rust; Rust's walk_forward returns an error rather than panicking on bad lengths. Rust is the one port with a typed error enum.

References

Dickey & Fuller (1979); Said & Dickey (1984); MacKinnon (2010) for the embedded response-surface coefficients and MacKinnon (1994) for the p-value surface it approximates; Engle & Granger (1987); Phillips & Ouliaris (1990); Granger & Newbold (1974); Johansen (1988, 1991) and Johansen & Juselius (1990); Osterwald-Lenum (1992); Uhlenbeck & Ornstein (1930); Kalman (1960); Bucy & Joseph (1968); Chan (2013) for the half-life and Kalman parameterisation; Gatev, Goetzmann & Rouwenhorst (2006); Vidyamurthy (2004); Sharpe (1994); Lo (2002); Khandani & Lo (2007); Avellaneda & Lee (2010); Numerical Recipes §11.1 and Golub & Van Loan §8.5 for Jacobi; Neumaier (1974) and Kahan (1965).

Quick start

git clone https://github.com/AshJha0/statistical-arbitrage && cd statistical-arbitrage

# Python reference (3.11; numpy required, pytest + statsmodels only for the tests)
cd python
pip install -r requirements.txt         # numpy; pytest + statsmodels for tests
PYTHONPATH=src python3 demo.py          # run the demo
PYTHONPATH=src python3 -m pytest -q     # run the tests (86 pass)
cd ..

# C++ (g++ 13, CMake >= 3.16, GoogleTest via find_package(GTest))
cd cpp
bash build.sh                           # = cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j2
./build/statarb_demo                    # run the demo (from cpp/, reads ../data)
ctest --test-dir build --output-on-failure   # run the tests (63 pass)
cd ..

# Rust (1.95, edition 2021; only dependency serde_json for the config loader)
cd rust
cargo run --bin demo --release          # run the demo
cargo test --release                    # run the tests (74 pass)
cd ..

# Java (21; JUnit 4 + Hamcrest — no Maven/Gradle)
cd java
bash build.sh                           # javac -Xlint:all -Werror everything into out/
bash demo.sh                            # run the demo main
bash test.sh                            # JUnitCore on all *Test classes (65 pass)
