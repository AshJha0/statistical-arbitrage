statistical-arbitrage

A self-contained statistical-arbitrage toolkit implemented four times — Python (reference), C++17, Rust and Java 21 — against one pinned numerical contract. OLS, the ADF unit-root test with MacKinnon (2010) finite-sample critical values, Engle–Granger, a Johansen-lite trace test with a native Cholesky + Jacobi eigensolver, a Kalman dynamic hedge ratio, rolling z-score signals and a pairs backtest with next-close execution, beta-hedged sizing and explicit risk limits are each specified down to the solver in API_SPEC.md, so all four languages reproduce 928 golden cases to 1e-6..1e-10, including full trade lists. No RNG at runtime; the reference is cross-validated against statsmodels before any golden is written. v1.2.1 adds a Python-only paper-trading layer and Rust/Java latency benchmarks. It runs on synthetic data and is a teaching and research-infrastructure library, not a trading system: see the limitations below.

What the latest review found and fixed. Two defects that a desk would hit in exactly the samples it uses. The backtester executed an entry signalled at day T−2 at the final close and force-closed it at that same close, reporting a phantom zero-day round trip that paid two costs and distorted trade count, win rate, holding period and Sharpe on every rolling daily re-run; the pinned rule now discards a pending entry at the end of data (a pending exit still executes), and the discard is golden-tested on hand-built spreads and property-tested over every truncation of the bundled pair. The ADF and Engle–Granger tests used asymptotic critical values, which on 60-day rolling screens systematically over-detect cointegration (the 2-variable 5 % value is −3.34 asymptotically but −3.46 at T_eff = 50); every port now evaluates the MacKinnon (2010) finite-sample response surface at the actual regression size and refuses T_eff < 20. Finite-parameter checks, day-column monotonicity and config re-validation were added in the same pass; 3 golden cases were added (24 total) with the 21 existing values unchanged. Known limits: P₀ = 1e3·I is not diffuse for four-digit prices, stops fire on favourable overshoots too, and returns are on notional, not compounded.
Limitations and what this is not. The bundled data is synthetic and the pair's generator is the model under test, so nothing here is evidence of edge (over 300 seeds without a break the out-of-sample Sharpe is 1.44, which recovers the generator). It is not tick-to-trade: the batch code allocates; only RollingZ and KalmanStep are O(1) per update (benchmarked, batch averages above), and RollingZ drifts about 5e-8 after 50,000 updates. It is not tradable as is: the four-language backtest uses fractional quantities and one close for both legs, and the Python paper layer, which adds whole shares, impact, borrow and limits, has assumed ADV and costs, checks limits at decision prices (drift can breach them), trades one pair and has no live broker. "Kalman adapts" is true of beta tracking only. Stops did not cap the damage on their own: a z-stop alone failed in the break, and with a P&L stop, max-hold and cool-down the out-of-sample result is still a loss. walk_forward is a single holdout; rolling_walk_forward is the rolling version. The risk limits (2 % / 60 days / 20 days) are round numbers, not tuned. Economics, labelled synthetic (300 seeds, best case): 1.70 % a year gross with no break and zero cost, break-even cost 16.7 bps a side, and a break window averages −12.6 %, so break-even is one break per about 10.5 years per pair: a small steady gain and a rare large loss. Real-data result (2026-11-05): null. A preregistered study on US equities, 2020-2026 holdout, gave net Sharpe -0.42 and about zero gross return, on a survivorship-biased universe (results). A second preregistered study, sector-residual reversal, was also null: holdout net Sharpe -0.32. Source: review/2026-11-05/REVIEW.md.

What's inside

OLS & ADF

ols.py: normal equations with a pinned LU solve, plain standard errors, t-stats and R². adf.py: augmented Dickey–Fuller with a fixed lag (default 1) or opt-in BIC selection (select_lag), constant and no trend, MacKinnon (2010) finite-sample critical values at the regression sample size (T_eff ≥ 20, maxlag ≤ 1000) and an interpolated approximate p-value that is never used for a verdict.

Engle–Granger & Johansen-lite

engle_granger.py runs the hedge OLS then the residual ADF against the 2- or 3-variable EG table; engle_granger_both tests both directions and requires both to reject. johansen.py is the 2–3 asset VECM with an unrestricted constant and k = 1 lagged difference, solved with a native Cholesky factorisation and cyclic Jacobi eigensolver against the Osterwald–Lenum 95 % trace table — no small-sample correction, trace test only, and collinear inputs are rejected.

Half-life & Kalman hedge

Half-life from an AR(1) fit on the spread, hl = −ln 2 / ln(1 + ρ), with the sentinels +inf and 0.0 both meaning "do not trade" — pinned in every port. kalman.py tracks a random-walk state (αₜ, βₜ) with RiskMetrics-style Q = δ/(1−δ)·I, a Joseph-form covariance update and innovation z-scores; r must be finite and positive.

Signals & pairs backtest

signals.py: a current-observation-inclusive rolling z-score (ddof = 1, zero-variance guard). backtest.py: a FLAT/LONG/SHORT state machine with next-close execution, beta-hedged legs by default (gross notional equal to capital at entry; equal_dollar optional), basis-point costs plus slippage, a P&L stop, |z| ≥ stop_z stops, a maximum holding time and a cool-down (all off by default), full metrics (total and annualised return, Sharpe, max drawdown, trades, win rate, holding period, turnover, stops), walk_forward (a single in-sample/out-of-sample holdout) and rolling_walk_forward (refit every block, stitched equity).

Streaming & research

RollingZ and KalmanStep update one tick at a time in O(1) with no allocation; the Kalman step matches the batch filter to 1e-12, the rolling z to 1e-9 (running sums, so batch stays the trading reference). research.py (Python only, not in the goldens): block-bootstrap Sharpe interval, probabilistic and deflated Sharpe, cost sensitivity, CUSUM break test, Benjamini–Hochberg, Kalman grid-MLE with innovation diagnostics and scan_pairs. They are judgement aids; none feeds the trading path.

Bundled data

pair_equity.csv: 1500 days of a cointegrated pair with true beta 1.7 and a break to 1.1 at day 1050. fx_triangle.csv: EURUSD vs a GBPUSD × EURGBP basket, cointegrated in logs, recovering the (1, −1, −1) triangle vector. random_walks.csv: two independent walks for the spurious-regression case. config.json holds the signal and cost parameters shared by all four demos; generate_data.py regenerates everything from fixed seeds.

Golden suite & testing

Every language loads the same golden.json and asserts each scalar within its tolerance, so a different lag convention, a non-Joseph update or a different z-score window fails immediately. Beyond goldens, each port carries the same behavioural suite: accounting identity, exact dollar neutrality at entry, next-close execution, the end-of-data discard rule on hand-built spreads with closed-form z-scores, the every-truncation "no zero-day trade" property, stop/re-entry timing, negative-equity metrics, walk-forward length checks and loader validation.

Paper trading & research protocol

Python only, outside the ported contract. Order state machine, paper broker, pair executor, risk engine, ledger and audit log; diagrams for the order lifecycle, paper flow, pair-entry leg risk, research protocol and sector-residual pipeline are in ARCHITECTURE.md. Both real-data studies were preregistered, run on the holdout once and reported as null.

Units, timing, scope

Prices are raw levels in whatever unit you pass (the FX example uses logs because cross-rate identities are multiplicative); alpha, beta, the Kalman r and P₀ share those units. One row is one equally spaced observation, 252 periods per year and the one-close execution lag are hard-coded. Out of scope: calendars and day-count, intraday data, financing and borrow, market impact, position compounding, rolling diagnostics helpers, Johansen deterministic-term variants and p-values.

Error contract

ValueError / std::invalid_argument / Err(StatarbError) / IllegalArgumentException for lengths, finiteness, emptiness, constancy, collinearity, parameter domains and window bounds at every public entry point; config structs are re-validated at run time in C++ and Rust; Rust's walk_forward returns an error rather than panicking on bad lengths; beta ≤ 0 and dead configs are errors in every port. Rust is the one port with a typed error enum.

Quick start

git clone https://github.com/AshJha0/statistical-arbitrage && cd statistical-arbitrage

# Python reference (3.11+; numpy required, pytest + statsmodels only for the tests)
cd python
pip install -r requirements.txt         # numpy; pytest + statsmodels for tests
PYTHONPATH=src python3 demo.py          # run the demo
PYTHONPATH=src python3 -m pytest -q     # run the tests (1248 pass)
cd ..

# C++ (g++ 13 or clang++, CMake >= 3.16; GoogleTest from the system, else fetched)
cd cpp
bash build.sh                           # = cmake -S . -B build && cmake --build build -j2 (Release by default)
./build/statarb_demo                    # run the demo (from cpp/, reads ../data)
ctest --test-dir build --output-on-failure   # run the tests (107 pass)
cd ..

# Rust (built on 1.99, declared minimum 1.85, edition 2021; only dependency serde_json for the config loader)
cd rust
cargo run --bin demo --release          # run the demo
cargo test --release                    # run the tests (115 pass)
cd ..

# Java (21; Maven, or javac with JUnit 4 + Hamcrest jars)
cd java
bash build.sh                           # javac -Xlint:all -Werror --release 21 into out/
bash demo.sh                            # run the demo main
bash test.sh                            # mvn test if installed, else JUnitCore (109 pass)
